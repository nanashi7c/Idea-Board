# Idea Board — プロジェクト指示

# 開発スタイル

KPI やカバレッジ目標が与えられたら、達成するまで試行する。
不明瞭な指示は質問して明確にする。

# コード設計

- 関心の分離を保つ
- 状態とロジックを分離する
- 可読性と保守性を重視する
- 条件分岐を、クラス構造やインターフェースに置き換えて、責務ごとに振る舞いを分離する
- 関数を小さく保ち、テスト可能な範囲に分割する。
- コントラクト層（API/型）を厳密に定義し、実装層は再生成可能に保つ

# ツール

- gh: GitHub CLI
- ripgrep: 正規表現でプロセスを検索するツール

## 推奨コマンド

- file 検索やfile 内文字列検索には ripgrep を使う。例: `rg --files` や `rg <pattern>`

## コマンド実行確認

- prompt なしで実行できるのは、許可済みルールに合致し、実行内容と影響範囲が明確なコマンドだけです。
- 破壊的操作、外部送信、認証情報や設定の変更、履歴改変、実行先が曖昧なコマンドは、実行前にユーザーへ確認します。
- `git push` や `git push -f` は直接実行しません。prompt なしで push する場合は、引数なしの `~/.codex/bin/safe-git-push` を使います。
- `~/.codex/bin/safe-git-push` が拒否した場合やコマンドが見つからない場合は、拒否理由を確認してからユーザーに方針を確認します。
- `gh pr edit` や `gh issue edit` は直接実行しません。prompt なしで自分が作成した PR / Issue を編集する場合は、`~/.codex/bin/safe-gh-edit <pr|issue> <number> [gh edit flags...]` を使います。
- `~/.codex/bin/safe-gh-edit` が拒否した場合やコマンドが見つからない場合は、拒否理由を確認してからユーザーに方針を確認します。
- curl は localhost / loopback / Docker network 内の private address 宛てなら prompt なしで実行可能

## 設計ドキュメントの参照（一次資料）

- 要件・設計・技術選定・規約は `docs/tmp/notion/` を一次資料として参照する（Notion 公開ページからの同期物・非コミット）。構成やタイトルは変わり得るので、その時点の中身を正とする。
- `docs/tmp/notion/*.md` は生成物。**直接編集しない**（次回同期で上書き）。内容変更は Notion 側で行う。
- 最新化は `npm run docs:sync`（または `node scripts/tmp/sync-notion-docs.mjs`）。フォルダが無い場合も同コマンドで生成する。
- 作業中に `docs/tmp/notion/*.md` の内容が実態と乖離している、または修正が必要と判断した場合は、直接編集せず、対象ページ・見出しと修正案（diff 形式）をユーザーへ提示する。反映は Notion 側でユーザーが行う。

## コミット規約

- コミットのtype一覧は08コーディング規約§10.1を正とする（`infra`を含む）。`skills/cmd-commit/references/commit-message.md`のprefix表は汎用スキルのデフォルトであり、本プロジェクトでは08の一覧を優先する。
- commitメッセージ・PR説明には設計ドキュメントへの参照を書かない（自己完結させる）。実装とドキュメントの対応づけは、設計ドキュメント側から該当PR/commitへリンクする一方向の運用にする。

特に指示がない限りは、日本語での受け答えをお願いします。

## skill の管理

- `skills/` を Claude / Codex 共通 skill の原本とする。
- `.claude/skills` と `.agents/skills` は生成物。直接編集しない。
- skill の追加・更新後は `pnpm skills:sync` で両方へ同期する。
- commit 前に `pnpm skills:check` で原本と生成物の一致を確認する。

## 実行主体（副作用のある操作）

- 副作用のある操作（ファイルの編集・新規作成、削除・上書き・外部送信、状態変更を伴うコマンド等）は原則ユーザーが行う。Claude は実行せず、コマンド案・差分案・ファイル内容案の提示に留める。
- 読み取り専用の操作（検索・閲覧・型チェック等）は、これまでどおり Claude が実行してよい。
- Claude が副作用のある操作を実行するのは、ユーザーが明示的に指示・許可した場合のみ。
