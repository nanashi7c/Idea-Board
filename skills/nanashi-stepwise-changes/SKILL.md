# Stepwise Changes

- 1ステップでは1つの小さな編集だけを扱い、原則として8ステップ程度をまとめて提示する。
- 「利用側から考える」「外側から内側へ実装する」順序で進める。
- 使用箇所を先に示し、そこで初めて必要になった関数やstateの定義を後に示す。
- stateは、そのstateを初めて使うコードと同じステップ内で定義する。
- importの追加だけを独立したステップにしない。
- その段階でまだ使わない関数、state、処理、抽象化を追加しない。
- 次のステップを提示するときは、その区切りでcommitまたはPRが必要か判断する。
- commitが必要な場合は、対象ファイルとcommit message案を提示する。
- PRが必要な場合は、PRタイトルと本文案を提示する。
- まだPRが不要な場合は、PRを作る予定の区切りを示す。

## 責務境界

- Plannerの計画出力には適用しない。
- Implementerがコード変更案を段階的に提示するときに適用する。
- コードとdiffを作成する責務はImplementerが持つ。
- このSkillは、差分の分割方法と説明順序だけを定める。
